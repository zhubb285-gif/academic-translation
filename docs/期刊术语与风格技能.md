# 期刊术语查证与风格技能

本次实现位于 academic-translation 项目，使用现有 Vue / FastAPI 技术栈。无需另装 Codex 技能或 React 插件。

## 页面使用

1. 翻译工作台 → 新建项目：选择目标期刊，打开“注入期刊风格 Skill”。创建后也可以在“原文与要求”页面、上传区域上方修改。
2. 点击“查看依据与规则”可查文章清单、DOI、已收集文本和完整 Skill。清空目标期刊或关闭开关后，后续翻译不再注入该 Skill，已生成译文不会被自动重写。
3. 上传后自动分段，调用项目的真实 AI 模型识别疑似专业术语、所属领域和检索英文候选，再查实际期刊文本、一级与二级信源。演示引擎不能执行 AI 识别；演示项目可使用已配置的真实默认模型，实际模型名会在进度中显示。缺少密钥会提示配置，不生成虚假识别结果。
4. 旧文档不用重新上传：进入“术语查证”，选择已配置模型，点击“AI 识别并查证”。长文按批处理并显示进度；失败或服务重启后可从已保存进度继续，不覆盖人工已确认译法。当前实现使用本地单进程后台任务，生产环境多进程部署需接入共享任务队列。
5. 术语列表展开箭头可查看原文句段、识别理由和模型。系统仅保存原文中连续出现的词组；这一步仍可能误判或漏识别，普通词可点击“排除”，遗漏可手动添加。识别理由和英文候选不是信源证据。
6. 术语详情并排显示“期刊文章”和“分级信源”。点击“填入人工裁决栏”仅选择候选；点击“确认采用”才保存最终译法。可填写理由，系统保留当时的证据快照与历史译法。
7. 自动查证不会覆盖先前的人工译法。翻译仍只使用人工已确认的术语表。

## 查证政策

- 英文候选由现有候选表、本地词表或模型语言分析提供，它们本身不算证据。
- 期刊文章是第一个实际检索的来源。即使有期刊用法，也继续检索一级来源，以便两侧对照。
- 一级完整官方词条命中且无明显领域冲突时，不继续检索二级；同形词条来自明显不同领域时会提示并继续查证。否则按一级、二级顺序尝试。三级不发出检索请求，不允许新增为证据或标记有效。
- 术语在线公开接口读取完整中英词条；其他已接通的站内搜索尝试获取相关详情页。二级补充 OSTI 公开摘要接口。
- 搜索结果页本身、自动生成的候选、只出现分散单词，都不会被引用为详情页证据。动态页面、登录或验证障碍明确列为未完成；无法访问不等于查无此词。
- 期刊和普通网页出现英文只标为“用法”，不自动当作中英对应证明。二级来源仍应人工核实独立性；同一库的多条结果不等于多个独立信源。

## 风格 Skill

`skills/journals/<期刊>/SKILL.md` 是可移植的技能文件；每刊另有 `references/articles.md` 和 `references/profile.json`。统计基于真实摘要，并提供3条有 DOI 的短开头摘录。它们用于信息组织和语气参考，不是官方投稿规则，也不等于微调模型。

摘要样本统计不能推导正文或 Methods 的硬性要求。论文事实、数值、单位、否定、因果边界以及人工确认术语优先。翻译和模型校对都读取所选 Skill；模型提示词不会注入整篇外部论文。

## 更新语料与重新生成 Skill

在项目的 backend 目录运行：

```sh
./.venv/bin/python scripts/collect_journal_library.py --target 40
./.venv/bin/python scripts/build_journal_skills.py
./.venv/bin/python -m unittest discover -s tests -q
```

`--target` 是每个学科查询的返回量，保留全部通过筛选的文章并按 DOI 去重。默认复用已有采集缓存；`--refresh` 才重新请求。语料保存到 `backend/app/data/journal_library/`，公开检索缓存位于被 Git 忽略的 `backend/data/literature_cache/`。

摘要的公开检索权限不等于全文下载或训练授权；后续微调需要另行筛选可训练许可及准备中英对照数据。
